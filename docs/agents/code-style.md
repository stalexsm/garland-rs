# Code style

## Язык

Человеческий текст в проекте — на русском: комментарии в коде, doc-комментарии, сообщения коммитов, заголовки PR, документация. Идентификаторы кода (типы, функции, переменные) — латиницей, как во всём проекте.

У публичных функций, типов и трейтов — doc-комментарий `///` с описанием контракта: что делает, что принимает, что возвращает.

В комментариях и doc-комментариях кода — никаких ссылок на issues: контекст задачи живёт в сообщении коммита, регрессии — в doc-комментариях тестов. Doc-комментарии публичного API вдобавок свободны от жаргонных помет в скобках: они попадают в rustdoc.

## Числа

Числа в бизнес-логике — только именованные константы или настройки; магических чисел в коде не оставляй. Тривиальные 0/1 (пустой индекс, единичный шаг) допустимы. Константы по умолчанию объявляй на уровне модуля с поясняющим комментарием.

## Практики

- Формат решает инструмент: `cargo fmt`; вручную форматирование не правим.
- Держим идиомы языка: подсказки clippy (гейт гоняет с `-D warnings`, см. `docs/agents/gates.md`).
- Изменения точечные: один PR — одна задача (см. `docs/agents/git-workflow.md`); попутные переименования и реформаты не подмешиваем.
