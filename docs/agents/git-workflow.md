# Ветки, коммиты и релизы

## Ветки

- Любая работа — в новой ветке, созданной от актуального `main`. Прямые коммиты в `main` запрещены.
- Имя ветки — `тип/краткое-описание` латиницей, тип — по типу будущего коммита: `feat/enrich-response-body`, `fix/worker-reconnect`.

## Коммиты

Conventional Commits с русским описанием: `feat:`, `fix:`, `doc:`, `build:`, `ci:`, `chore(deps):`.

## CHANGELOG

`CHANGELOG.md` генерируется `git-cliff` по `cliff.toml` — не редактируй вручную.

Основные команды:

- просмотр не вышедших изменений — `git-cliff --unreleased`;
- релизная секция поверх существующего файла — `git-cliff --unreleased --tag X.Y.Z --prepend CHANGELOG.md` (заголовок встанет с тегом до коммита самого тега);
- полный пересбор файла — `git-cliff -o CHANGELOG.md`;
- следующая версия по коммитам считается самим `git-cliff`: `git-cliff --bumped-version` (печать) и `git-cliff --bump` (генерация с новой версией).

Релизный коммит называй `chore(release): prepare for X.Y.Z` — `cliff.toml` исключает его из будущих генераций.

## Версия и релиз

- Версия задаётся один раз в `[workspace.package]`.
- Релиз: git-тег без префикса (`0.4.0`, как все исторические теги) на релизном коммите в `main` после мерджа PR — не в ветке.
- GitHub Release создаётся на этот тег с именем `vX.Y.Z`.
