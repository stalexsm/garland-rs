# Память Текущего эффекта: key-value на NVS-разделе

Индекс Текущего эффекта должен переживать отключение питания и жить вне OTA-Слотов, поэтому он хранится в NVS-разделе финальной таблицы (nvs + otadata + ota_0 + ota_1). Готового NVS формата ESP-IDF в no_std-стеке esp-hal нет (модуль NVS есть только в std-крейте esp-idf-svc), поэтому запись ведёт крейт `sequential-storage` (map API) поверх NorFlash-вида раздела из `esp-bootloader-esp-idf`: циклическая перезапись, износостойкость и восстановление после сброса питания посреди записи решены проверенным крейтом. Шов машины Гирлянды — трейт `EffectMemory` (синхронные `save`/`load`): прошивочная реализация пишет во флеш прямо при переключении (запись — единожды на нажатие, миллисекунды), стартовое чтение — при создании хранилища; ошибки носителя не останавливают Гирлянду, а номера вне Реестра (сузился после обновления) считаются отсутствием сохранённого.

## Considered Options

- **NVS формата ESP-IDF** — эталонный смысл слова «NVS», но в no_std Rust не реализован: esp-storage и esp-bootloader-esp-idf модуля NVS не содержат, esp-idf-svc требует std.
- **Свой мини-формат в секторе** — без новых зависимостей, но логику стирания, износа и восстановления после сбоя питания пришлось бы придумывать и тестировать самому.
- **sequential-storage (map) поверх NVS-раздела** (принято) — ключ-значение из коробки, износ и сбои питания решены не нами; раздел по-прежнему `nvs` из таблицы, так что формат — внутреннее дело хранилища.
