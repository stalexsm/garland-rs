# 🎄 garland-rs

Умная новогодняя гирлянда на ESP32-C6: адресная лента WS2812B, прошивка на Rust (`no_std`, esp-hal), обновление по воздуху прямо из браузера.

## ✨ Возможности

- **Двенадцать эффектов-аддонов** — классические эффекты:«Огонь», «Снегопад», «Матрица», «Звездопад», «Конфетти», «Шарики», «Синусоиды», «Радуга диагональная», «Лава», «Облака», «Плазма», «Радужные переливы»; смена эффектов — плавным кроссфейдом (~0,8 с).
- **Одна кнопка** — короткое нажатие листает эффекты по кругу, длинное гасит ленту (покой). Номер эффекта живёт в NVS и переживает выключение питания и обновления прошивки.
- **OTA-обновление из браузера** — образ прошивки заливается на веб-страницу гирлянды; если новая прошивка не заработала, загрузчик сам откатывается к прежней.
- **Сеть не обязательна** — эффекты и кнопка работают без Wi-Fi, сеть нужна только для обновления.
- **Гибкая геометрия** — размер матрицы, раскладка (змейка или прямая, по рядам или столбцам) и пины задаются при сборке.

## 🔌 Железо

| Что | Детали |
|---|---|
| Плата | ESP32-C6 (RISC-V), флеш от 4 МБ; проверено на DevKitC-1 |
| Лента | WS2812B (порядок GRB), данные — GPIO 10 по умолчанию |
| Кнопка | GPIO 9 по умолчанию; на DevKitC-1 это кнопка BOOT, паять свою не нужно |

## 🛠️ Инструменты

Нужны стабильный Rust и [espflash](https://github.com/esp-rs/espflash). `espup` не требуется — ESP32-C6 это RISC-V.

1. Rust: канал, компонент `rust-src` и target `riscv32imac-unknown-none-elf` прописаны в `rust-toolchain.toml` — rustup подтянет их сам при первом `cargo`-вызове.
2. espflash:

   ```text
   cargo install espflash --locked
   ```

## ⚡ Первая прошивка — по кабелю

Подключите плату по USB и выполните из каталога `crates/fw`:

```text
cargo run
```

Заливает прошивку, таблицу разделов (`nvs` + `otadata` + два OTA-слота) и собственный загрузчик с автооткатом, затем открывает монитор с логами. Настройки заливки живут в `crates/fw/.cargo/config.toml`.

Первые секунды прошивка показывает **тестовую сетку раскладки**: белый бегунок идёт по ленте в порядке змейки, красный пиксель держит стартовый угол — удобно проверить, что подключение и раскладка в сборке совпадают с реальной укладкой.

Дальше обновляйтесь по воздуху — см. [🚀 OTA-обновление](#-ota-обновление).

### Параметры сборки

Задаются переменными окружения на этапе сборки, дефолты — отладочный стенд 8×8:

| Переменная | Значения | Дефолт |
|---|---|---|
| `MATRIX_W` | ширина матрицы в пикселях | `8` |
| `MATRIX_H` | высота матрицы в пикселях | `8` |
| `LAYOUT` | `serpentine-rows`, `plain-rows`, `serpentine-cols`, `plain-cols` | `serpentine-rows` |
| `START_CORNER` | `top-left`, `top-right`, `bottom-left`, `bottom-right` | `top-left` |
| `LED_PIN` | GPIO ленты (ESP32-C6: 0..=30) | `10` |
| `BUTTON_PIN` | GPIO кнопки (0..=30; BOOT на DevKitC-1 — `9`) | `9` |
| `MAX_BRIGHTNESS` | потолок яркости канала, 0..=255 | `64` |
| `TEST_GRID_SECS` | длительность тестовой сетки, секунд (0 — выключить) | `8` |
| `DRIVER_GATE` | `1` — диагностический режим гейта драйвера вместо гирлянды | `0` |
| `WIFI_SSID` | имя домашней сети (пустое — офлайн-режим без сети) | — |
| `WIFI_PASS` | пароль Wi-Fi | — |

Примеры:

```text
MATRIX_W=16 MATRIX_H=32 cargo build                  # матрица окна 16×32
WIFI_SSID=HomeNet WIFI_PASS=secret cargo run         # сборка, заливка и сеть
```

## 📡 Сеть и веб-страница

Если при сборке заданы `WIFI_SSID`/`WIFI_PASS`, гирлянда подключается к домашней сети (STA, авто-переподключение) и получает адрес по DHCP. В роутере устройство видно под именем **garland** — проще всего найти его в списке DHCP-клиентов (mDNS нет, `garland.local` не работает).

На `http://<IP-гирлянды>/` — страница с версией прошивки и формой OTA-обновления.

> ⚠️ Сервер говорит по HTTP без TLS — обновляйтесь только внутри домашней сети.

## 🚀 OTA-обновление

1. Соберите образ (те же переменные окружения, что и при обычной сборке):

   ```text
   cd crates/fw
   WIFI_SSID=HomeNet WIFI_PASS=secret cargo build --release
   espflash save-image --chip esp32c6 \
       target/riscv32imac-unknown-none-elf/release/fw garland.bin
   ```

2. Залейте образ — через форму на странице гирлянды (кнопка «Залить и перезагрузить»):

   ```text
   curl --data-binary @garland.bin http://<IP-гирлянды>/ota
   ```

Во время заливки не отключайте питание.

### Почему это безопасно

- Образ пишется в **неактивный слот**; активация и перезагрузка — только после полной записи. Обрыв соединения или битый образ прежнюю прошивку не трогают.
- После старта новая прошивка **подтверждает свой слот**. Пока подтверждения нет, обновление считается неудавшимся: если новая прошивка зависла, достаточно перезагрузить питание — загрузчик пометит слот невалидным и запустит прежнюю версию (**откат**).
- Автооткат даёт только собственный загрузчик `crates/fw/bootloader/esp32c6-rollback.bin` (ESP-IDF с `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`; прекомпилированный загрузчик espflash откат не умеет). Рецепт пересборки — `crates/fw/bootloader/README.md`.
- Раздел NVS лежит вне OTA-слотов, поэтому обновление не сбрасывает память эффекта.

## 🕹️ Управление кнопкой

| Действие | Результат |
|---|---|
| Короткое нажатие | следующий эффект по кругу, кроссфейд ~0,8 с |
| Длинное нажатие (~0,8 с) | покой — лента полностью чёрная |
| Короткое нажатие из покоя | текущий эффект возвращается мгновенно |

Последний выбранный эффект сохраняется в NVS: после подачи питания гирлянда включается с ним же.

## 🧩 Свой эффект

Эффекты — аддоны: один крейт в `crates/effects/` на эффект (решение ADR-0001). Чтобы добавить свой:

1. Заведите крейт с реализацией трейта `Effect` из `garland-core` (эффекты не знают ни о железе, ни о сети — только фреймбуфер и время).
2. Добавьте зависимость в `crates/fw/Cargo.toml`.
3. Пропишите одну строку в реестре `REGISTRY` (`crates/fw/src/control.rs`).

На ленту новый эффект попадает вместе с новой прошивкой — соберите образ и залейте по OTA.

## 🧪 Разработка

- Гейты CI: `cargo fmt`, `cargo clippy` (хост и целевой таргет), `cargo test` — детали в `docs/agents/gates.md`; полный список джоб (MSRV, skylos, semgrep) — в `.github/workflows/ci.yml`.
- На хосте крейт `fw` собирается пустой заглушкой, поэтому хост-тесты идут без железа; прошивочный код компилируется только под `riscv32`.
- Релизы: CHANGELOG ведёт git-cliff, тег ставится без префикса (`1.2.3`), GitHub Release создаёт workflow по тегу.
